# CVB timing: 30 modules per arm

The active configuration in `src/timing_config.h` is mode 3, scope 0, N=30:
30 simulated modules per arm, 60 total. Only one USB-powered SPIN is needed.
No PWM/power outputs or ADC acquisition are initialized.

The actual CVB sorting functions are unchanged. The output mask and its reporting
path now use 64 bits (upper bits 0..29, lower bits 30..59). Tied test vectors
are built from initialized five-element blocks, preserving the N=5/N=10 cases.
The capture and analysis scripts support N=5, 10, 20 and 30.

Startup runs 3,191,481 correctness combinations, including all nine current-sign
pairs and all 31 x 31 insertion-count pairs over 369 input vectors. This is a
bounded input set, not exhaustive enumeration of 30! permutations or 3^30 vectors.
The self-test may take substantial time before USB reporting starts. Expected:

```text
CVB_SELFTEST,PASS,checks=3191481,failures=0
```

The repeating timing campaign has 930 cases, 2,790 batches and 2,790,000 calls.
At a 500 us period (2 kHz) it takes nominally 1395 seconds (23 min 15 s), excluding startup.
The capture timeout defaults to 1800 seconds; increase it if startup requires
more time. A timeout is not proof of a correctness failure.

From the project root, using PlatformIO and Python with pyserial installed:

```powershell
pio run -e USB
pio run -e USB -t upload
python benchmarks/cvb/capture.py benchmarks/cvb/results/N30_both.log --mode 3 --scope 0 --modules-per-arm 30 --timeout 1800
python benchmarks/cvb/analyze_campaign.py benchmarks/cvb/results/N30_both.log --output-dir benchmarks/cvb/results/processed
```

Close other serial readers before upload/capture. Upload replaces the attached
board firmware. Capture defaults to serial number 423250070032003B; use
`--serial-number` for another board. Use a fresh log filename for each run.
For one arm, select mode 3 with `select_run.py 3 --scope 1` (upper) or `--scope 2`
(lower), rebuild/upload and pass the matching scope to capture.

Host regression checks:

```powershell
python -m unittest discover -s benchmarks/cvb/tests -v
```

The firmware-header regression requires clang++ or g++ and skips if neither is
available. It runs the actual startup self-test for all four supported sizes and
checks all output bit positions and tied-vector independence from prior contents.
Host checks and compilation do not establish execution time on the STM32.
Board execution must confirm startup PASS, complete capture, and deadline/overrun
measurements before claiming the 500 us budget is met.

## Long Windows paths

The ARM archiver may report missing object files when this checkout is deeply
nested on Windows. Use a physically shorter project path; a `subst` alias alone
can be resolved back to the original long path by Zephyr. Rebuild at the shorter
path before uploading; an image left in the original build directory may be stale.
